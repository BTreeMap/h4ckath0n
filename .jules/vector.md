## YYYY-MM-DD - Centralized Pydantic Field Normalization

**Learning:** Pydantic `Annotated` combined with `AfterValidator` can be used to centralize type normalization and validation logic into reusable field types, avoiding repetitive `@field_validator` methods across multiple models. `AfterValidator` is generally safer than `BeforeValidator` for string manipulations like `.strip()` because it runs after Pydantic type coercion, preventing `AttributeError` for non-string types and ensuring standard `422 Unprocessable Entity` handling. The `Field` constraints (like `max_length`) applied in the reusable type are merged with the `Field` metadata (like `description`) applied at the model attribute level.
**Action:** When standardizing fields like display names that require both specific lengths and stripping/validation across multiple Pydantic models (e.g. auth and passkey schemas), prefer defining a reusable `Annotated` type with `AfterValidator` rather than duplicating the `@field_validator` blocks in every model class.
